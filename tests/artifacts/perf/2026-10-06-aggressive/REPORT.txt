What changed and where the savings came from

1. ln avoids constructing and destroying a Clap command for simple two-operand
   invocations using only -s/-f/-n/-T. It handles clusters, interspersed flags,
   and --; all other forms fall back to the complete existing parser before
   filesystem side effects. Operand paths move out of the captured argv.
   The original exec/link/replace_link operations, including atomic replacement,
   remain intact. Help, errors, backups and interactive paths use the full code.
   Callgrind instructions drop from 157,021 to 39,283 in the final ln profile,
   about 75%. The reduction removes parser construction and its allocation/free
   work. Final musl _start_c accounts for 23,638 instructions (60.17% of user-space
   instructions); this is not a statement that 60% of wall time is relocations.

2. true first received a C-main wrapper that returns before Rust runtime startup
   for silent invocations. This takes 50.15 us. Its remaining 20,482 instructions
   include 19,102 in musl _start_c (93.26%), motivating the next step.

3. The selected true has a small custom Linux/x86-64/musl ELF entry, before even
   musl startup. Silent invocations call exit_group(0) directly. Exactly one
   --help or --version argument jumps into the original _start; the full existing
   implementation remains in the same executable, without a second exec.
   No-argument execution takes six machine instructions including the exit
   syscall, verified from this binary's disassembly. Strace records only execve
   and exit_group. Callgrind reports 3 instructions because the terminating
   syscall block is not fully counted; do not interpret that as a literal total.
   Sample minor faults drop 41 -> 33 -> 17 across previous/CRT-return/raw-entry.
   No absolute pointers, relocations, heap, TLS or Rust runtime are needed on
   the quiet path. Original stack and rdx are preserved for the normal fallback.
   PIE/ASLR and non-executable stack are retained. This is explicitly an optional
   platform-specific startup experiment: quiet invocations skip constructors,
   runtime initialization and destructors. Instrumentation that depends on those
   hooks would need explicit treatment. It is not a general Rust runtime design.

4. Packed RELR was tested and rejected. Multicall true rises from 197.14 to
   208.99 us; Callgrind instructions rise 378,574 -> 455,370. The packed table
   shrinks relocation metadata, but decoding it executes more startup work on
   this toolchain. The final build keeps ordinary RELA.

Final multicall true still spends 365,672 of 378,604 instructions in _start_c,
with 26,058 relative relocations. Final multicall ln has the same 365,672 startup
instructions, of 382,919 total. This explains why avoiding parser work helps ln
but does not remove the large multicall startup floor.

GNU binary profiles also show dynamic-loader lookup/relocation work dominating
these tiny commands. GNU true has 154,613 user-space instructions; GNU ln 193,094.
Original Rust glibc standalones have 510,930 and 684,744, respectively, including
loader work and eager localization. No GNU implementation source was read or
copied; symbol-level profiles use callgrind_annotate --auto=no.

Files remain large: final true is 5,025,336 bytes and ln 6,890,672 bytes, including
level-1 debug information. Previous true was 5,025,280 bytes. Removing executed
startup work mattered far more here than total on-disk size. Cold-cache, memory
pressure and long-running musl throughput were not measured in this experiment.

Measurement controls and limits
Everything was built, tested, benchmarked and profiled on ssh wx-workstation:
AMD Threadripper PRO 9985WX, Ubuntu 24.04.4, Linux 6.17.0-1032-oem; rustc 1.94.1,
LLVM 21.1.8; installed GNU coreutils 9.4; hyperfine 1.20.0. CPU affinity 4,
performance governor, warm cache, LANG=LC_ALL=C. Shared host, no isolation or
system tuning. No builds/tests/profiles ran during native timing. Each case
runs in 8 shuffled blocks of 1,000 launches with 20 warmups via hyperfine -N.
ln repeatedly replaces a symlink on ext4/NVMe; it includes real filesystem work.
All outliers are retained in the raw data (including two ~43 ms scheduler stalls
in intermediate builds). Pooled p95 is reported separately from the median.

Rust release opt-level 3, fat LTO, one codegen unit, panic=abort, debug=1,
force-frame-pointers=yes. Standalones use separate Cargo invocations. Multicall
uses feat_os_unix_musl across controls (no stdbuf). No PGO or CPU-native tuning.
Static musl CRT/runtime comes from Rust's target; native dependency compilation
uses the private tools/musl-gcc wrapper. Perf is unavailable (paranoid=4), so
Callgrind/strace/resource snapshots are separate explanatory profiles, not
substitutes for native timings or native cycle counts. RSS snapshots sometimes
report zero for very short processes; they are not reliable memory-use estimates.
